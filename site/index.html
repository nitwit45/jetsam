The Mac cleaner that previews every delete.

Jetsam removes what your tools can regenerate: node_modules, build output, package caches, stale git worktrees. Every path is listed with its size before it can be removed, and files go to the Trash.

Download for macOS brew install --cask nitwit45/tap/jetsam

Free, MIT licensed. macOS 13 or later, Apple silicon and Intel. Not notarized: what that means for the first launch.

Pick how far it reaches

Choose a mode and scan. Overview shows what a clean would free, by category, and nothing is removed until you have been through the list.

Each mode includes the ones before it. The first two stay out of your projects. Deep and Full go into them, and only for folders a build can recreate.

Light
App caches and logs, .dmg and .pkg installers in Downloads older than 14 days, Homebrew cleanup, Docker dangling images and build cache.
Standard
Package manager caches (npm, pnpm, bun, pip, cargo, Gradle, Playwright), Xcode derived data and old device support, unused Android virtual devices.
Deep
Build folders in projects with no commit for 14 days, stale merged worktrees, unused Docker images, and AI session logs older than 45 days, which are listed for you to review.
Full
Build folders in the projects you are working on now. Nothing git tracks is touched.

Every path and rule is in docs/modes.md.

Big files you stopped opening

Aged Files lists files of 250 MB or more that you have not opened in 90 days, largest first, by Spotlight's last-used date. Both numbers are adjustable.

Nothing here is selected for you. Reveal a row in Finder to see what it is, or move it to the Trash.

Memory nothing is using

Jetsam samples every process every 10 seconds and labels what it finds: helpers whose parent has exited, processes that keep growing, idle ones, headless browsers that automation left running.

Reclaim ends the orphaned helpers and flushes the file cache. Anything else is ended only if you tick it and confirm. A soft restart quits and reopens Chrome, VS Code or Cursor, and refuses while a Claude Code agent is running inside the editor.

What it leaves alone

Jetsam deletes files and ends processes, so these rules are the product. Each one is enforced in code, at scan time and again right before removal.

  • Anything git tracks Tracked files are skipped, even inside a build folder. If git cannot answer, the file counts as tracked.
  • Folders that only look like build output build, dist and similar names count only inside a git repository or next to a project file such as package.json.
  • Docker volumes and containers Only images and the build cache are pruned. The disk images of Docker Desktop, OrbStack, Colima, Lima, Podman and Rancher Desktop are never listed.
  • Worktrees with work in them Only worktrees under .claude/worktrees/ are considered. One goes only when nothing in it is uncommitted or unmerged, git has been quiet for 24 hours and no process is working inside it.
  • Credentials, mail and photos Keychains, Mail, Messages, Photos libraries, iCloud Drive, device backups, ~/.ssh, ~/.gnupg, ~/.aws and ~/.kube are refused in every mode.
  • Running agents and the app in front Reclaim never ends a running Claude Code agent, what it started, the terminal or editor hosting it, or the app you were last using.
  • Jobs you left running A process started from a terminal window is never treated as an orphan, with nohup or without.
  • The network Jetsam makes no network requests. No telemetry, no crash reports, no update check.

Files go to the Trash, and Undo puts the last clean back for as long as its items are still there. Each claim, the code behind it and the test that checks it: docs/safety.md.

Measured on one machine

I built Jetsam after my MacBook Air (M4, 16 GB RAM, 256 GB SSD) ran out of room on 3 Nov 2026. I cleaned it by hand that day, before Jetsam existed, so these are the numbers that made me write it, not its results.

Data volume 95.5% full, 11 GB free
Regenerable build folders under home 62 GB, 40.2 GB of it in 137 node_modules folders
Stale git worktrees in one repository 105 worktrees, 29 GB
Swap 9.5 GB of 11 GB used, 116 million swap-outs in 6 days of uptime

Afterwards the volume had 33 GB free. Later, nine headless Chrome instances started by QA scripts under two coding agents held about 5.5 GB. This is one machine on one day; the method and its caveats are in docs/measurements.md.

Before you install

Know this first

  • It is not notarized. Installed with Homebrew it opens normally. From the DMG, macOS blocks the first launch and the README has the two steps.
  • It wants Full Disk Access to see the Trash and some app data. Without it Jetsam still works and tells you what it cannot see.
  • It is tested on Apple silicon. The Intel half of the universal build has only been run under Rosetta.
  • What it removes downloads or rebuilds the next time a project needs it. On slow or metered internet that cost is real.
  • The weekly clean and --headless run with no preview. They remove only what a scan would preselect, in Light or Standard.

Use something else if

  • You want a command line tool to script: Mole or npkill.
  • You only want to see what fills the disk: GrandPerspective or DaisyDisk.
  • You need to uninstall apps: AppCleaner.
  • Your Mac is managed and blocks unsigned apps.
